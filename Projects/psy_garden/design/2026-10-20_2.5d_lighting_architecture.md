# 2.5D AI 绘图动态光影与多部位赋色架构方案 (2.5D Lighting & Tinting Architecture)

**日期**：2026-10-20  
**适用项目**：心灵花园 (`psy_garden`)  
**状态**：技术方案设计 (Design Draft)

---

## 1. 背景与核心目标

在《心灵花园》中，植物资产目前由 AI 生成底图，经抠图分通道后通过纯 CSS 3D (`preserve-3d` + `rotateX`/`rotateZ` + Billboard 逆向旋转) 在 DOM 中呈现。
现有架构存在两个核心局限：
1. **光影缺乏体积感**：CSS 滤镜（`brightness`, `mix-blend-mode`）只能做全局增亮变暗，无法产生真实受光面与背光面的物理明暗交界线。
2. **变色依赖 `hue-rotate` 滤镜**：各部位独立上色时使用色相偏移角度，难以精准还原设计师设定的特定莫兰迪/情绪色板。

本方案旨在引入 **“Albedo (部位底图) + Normal Map (法线贴图) + WebGL 混合光源”** 架构，实现：
- **生成时自由指定部位固有色**：在植物生成/种植时，各部位可被赋予精确的十六进制颜色（如暖木色树干 + 暖金叶片）。
- **动静态光源物理响应**：全场支持**局部点光源**（中央燃香、漂浮思绪微光、鼠标交互）与**全局天光**（晴日、黄昏夕阳低角度斜射、阴天漫射、月夜冷暖交织）。
- **零 GPU 成本资产扩展**：在 Python 打包脚本中集成快速法线计算，完全不依赖高配显卡。

## 2. 渲染管线与光照计算架构

### 2.1 整体分层：DOM UI 与 WebGL 世界层解耦

为保留文字排版、流式吹散动画及毛玻璃弹窗的极致 Web 体验，系统采用混合渲染架构：

```text
┌────────────────────────────────────────────────────────┐
│  Layer 3: 沉浸心流输入舱 / 历史气泡 / 金句浮窗 (原生 DOM) │
├────────────────────────────────────────────────────────┤
│  Layer 2: HUD 控制台 / 燃香进度条 / 快捷交互 (原生 DOM)   │
├────────────────────────────────────────────────────────┤
│  Layer 1: The Garden 世界层 (全屏透明 WebGL Canvas)      │
│   - 正交相机 (OrthographicCamera, 2.5D 视角)            │
│   - 网格地面 (Grid Floor Billboard)                    │
│   - 植物立绘平面 (MeshStandardMaterial / Custom Shader)│
│   - 多层光源系统 (Ambient + Directional + PointLights)  │
└────────────────────────────────────────────────────────┘
```

### 2.2 核心光影数学模型

每株植物在屏幕上的最终像素色彩由**两阶段物理模型**决定：

$$\text{Pixel Color} = \mathbf{C}_{\text{albedo}} \times \Big( \mathbf{L}_{\text{ambient}} + \sum_{i} \mathbf{L}_{\text{dir}, i} \cdot \max(0, \vec{N} \cdot \vec{L}_i) + \sum_{j} \mathbf{L}_{\text{point}, j} \cdot \max(0, \vec{N} \cdot \vec{P}_j) \cdot \text{Atten}_j \Big)$$

1. **第一阶段：部位固有色解算 ($\mathbf{C}_{\text{albedo}}$)**：
   植物资产由 2~3 个通道（`layer_red`, `layer_green`, `layer_blue`）组成。各通道在生成时被赋予对应的目标情绪颜色：
   $$\mathbf{C}_{\text{albedo}} = \sum_{k \in \{r, g, b\}} I_k(u, v) \times \mathbf{C}_{\text{target}, k}$$
   其中 $I_k(u, v)$ 为该部位的去色明暗灰度值（Luminance），$\mathbf{C}_{\text{target}, k}$ 为该部位的固有色（如 `#e6c35c`）。
2. **第二阶段：法线受光计算 ($\vec{N}$)**：
   植物表面法线向量 $\vec{N}$ 从共用的 `normal.png` 贴图中读取，与光源方向计算点积，自然呈现出朝光面高光、背光面幽暗。

## 3. 多光源系统设计 (天气、昼夜与交互点光源)

系统通过统一的光源管理器统一调节，不改动任何植物资产文件：

| 天气/时间模态 | 光源构成 (Three.js Lights) | 光源参数配置 | 植物视觉响应与禅意氛围 |
| :--- | :--- | :--- | :--- |
| **☀️ 晴朗日光 (Daylight)** | `DirectionalLight` (主天光)<br>+ `HemisphereLight` (环境) | 俯角 $65^\circ$，色温 `#fffaf0`，强度 1.2<br>天空色 `#d4e6f1`，地面色 `#7d6608` | 植物整体色彩饱满通透，叶片边缘立体明朗，地面投下短阴影。 |
| **🌇 夕阳黄昏 (Sunset)** | `DirectionalLight` (斜阳)<br>+ `AmbientLight` (暮色) | 俯角 $15^\circ$ (左上方极低斜射)，色温 `#ff7b3a`，强度 1.5<br>暮色深紫灰 `#4a3b5c`，强度 0.4 | **最震撼效果**：每株植物左侧与叶脉凸起被镀上金红光边（Rim Light），右侧自然隐入温柔暮色。 |
| **☁️ 阴天/雨雾 (Overcast)** | `HemisphereLight` (漫反射)<br>（几乎关闭 DirectionalLight） | 天空雾灰青 `#b8c4cc`，强度 0.8<br>地面湿土暗色 `#4a4639`，强度 0.5 | 无强烈单向反差与硬光斑，法线呈柔和上下渐变，类似水墨淡彩的潮湿内敛质感。 |
| **🌙 静谧月光 (Moonlight)** | `DirectionalLight` (清冷月光)<br>+ `PointLight` (中央燃香)<br>+ `PointLight` (交互微光) | 月光色 `#7aa2f7`，强度 0.5，右上角斜射<br>燃香暖火光 `#ff9944`，带轻微呼吸抖动<br>光点色随心流状态动态流动 | **冷暖双色交响**：植物朝月一侧泛银蓝微光，朝香一侧映出温暖橘光，黑夜与火光对比鲜明。 |

## 4. 资产生成管线升级方案 (`build_plant_asset.py`)

为保证在无独立显卡环境下顺畅运行，法线与灰度图在打包时一并完成：

1. **图层去色与纯净明暗提取**：
   - 将原切片图层从带色像素转化为纯粹的灰度明暗图（保留原有纹理明暗对比）。
2. **纯算法 0.1 秒法线生成（无 GPU 依赖）**：
   - **轮廓体积感（宏观）**：利用 Alpha 通道的距离变换（Distance Transform / Signed Distance Field），计算出从植物边缘向内部隆起的弧度，生成宏观曲面法线。
   - **微观凹凸纹理（微观）**：利用原图明暗度的 Sobel 算子，提取叶脉、枝干皮纹的梯度向量。
   - **向量融合与归一化**：将宏观法线与微观法线在切线空间融合，打包保存为标准紫色系 `normal.png`。
3. **可选升级（深度模型）**：
   - 部署轻量级 `Depth-Anything-V2-Small` (ONNX Runtime CPU 版)，推理一张 250px 植物仅需 ~0.8s，自动输出带前后叶片遮挡层级的 `depth.png`。
