# 卡片存储模型：一切皆卡片

> 本文取代 `idea.md` 中"扁平单目录 + 00_Inbox"的旧描述，也不再沿用 Ulysses 式"项目 = 一篇线性长文"的模型。

## 1. 核心原则

1. **一切皆卡片**：卡片、编排、项目都是同一种东西，即一个带 `id` 的 Markdown 文件。
2. **身份只认 `id`**：文件路径和文件名可以随意移动、重命名，不影响身份。
3. **全局等价**：无论卡片存放在哪个目录，在 Finnegan 中地位平等：都会出现在散落视图中，都能被搜索、被嵌入。
4. **文件即真相**：Markdown 文件是唯一真相源（Single Source of Truth），RxDB/SQLite 只是响应式缓存。
5. **界面状态不进头部**：坐标、旋转、景深等纯 UI 状态只存 RxDB，避免污染 Git 历史。

## 2. 生命周期分层

```
纯内存 (Volatile)          Bugu 发现的网络内容，未保存；重启即消失
   │  用户保存 (PromoteTempCard)
   ▼
Scattering/                已转正的原件，扁平存放（没有上游）
   │  被嵌入某个编排 / 在某个项目上下文中编辑
   ▼
Weaving/<项目>/            该项目上下文中产生的分支卡与新卡片
```

- 原先的 "Inbox" 概念取消：**保存即转正**，转正后直接进入 `Scattering/`。
- 纯内存层即现有的 `CardManager.tempCards`（见 `kb/knowledge.md` §2）。
- `Scattering/` 与 `Weaving/` 的区别**仅在物理存放**，逻辑上是同一片海。

## 3. 目录结构

```
<数据根>/
├── Scattering/
│   └── 20261011-1512-短标题.md
├── Weaving/
│   └── 论乔伊斯/
│       ├── 20261011-1600-论乔伊斯.md   ← 项目根卡（编排卡）
│       └── 20261011-1630-xxx.md        ← 在本项目上下文中产生的分支卡
└── .finnegan/
    └── bases/<sha256>.md               ← 分支 base 快照库（内容寻址）
```

- 文件名：`YYYYMMDD-HHMM-短标题.md`，便于人读和排序；**不承担身份**。
- 完整的目录结构、配置组织和外部项目规则见 `design/tentative/2026-10-11_data_directory_layout.md`（以它为准）。

## 4. 头部信息（YAML Frontmatter）

```yaml
---
id: 01JA8X...          # 必填。ULID：唯一，且可按时间排序
created: 2026-10-11T15:12:00+08:00   # 必填
updated: 2026-10-11T15:30:00+08:00   # 必填
source: bugu           # 可选。local | bugu | atproto | mobile
source_url: https://...# 可选
echo_of: 01JA7Y...     # 可选。是哪张本地卡片触发了这次 Bugu 搜索
tags: []
upstream: 01JA6Z...    # 可选。有此字段即为分支卡
base: sha256:3f2a...   # 可选。分支那一刻 upstream 内容的 hash
publish: false
at_uri:                # 可选。发布到 AT Protocol 后回填
---
```

**刻意不加的字段**：`kind`（是否为编排由正文推导）、`weight`、`status`、坐标与景深。

## 5. 卡片间的两种关系

| 关系 | 表示方式 | 含义 |
|---|---|---|
| **嵌入**（编排） | 正文中的 `![[id]]` | "我由这些卡片组成"，可以层层嵌套 |
| **分支**（血缘） | 头部的 `upstream` + `base` | "我是从那张卡片分出来的"，写时复制 |

### 5.1 编排

- 正文中含有 `![[id]]` 的卡片就是**编排卡**；编排可以作为下一个编排的输入（嵌套嵌入）。
- 编排中允许出现**胶水文字**（过渡语、章节标题等），它们属于编排卡自己的正文。
- 在编排中嵌入任意卡片（包括直接来自 `Scattering/` 的卡片）是常规操作，不需要先"加入项目"。
- **线性长文只是编排的一种产物**，不是项目的定义。
- **约束：嵌入不得成环**（A 嵌 B、B 又嵌 A），写入时必须做环检测。
- 暂时只支持 Markdown 编排；画布、关系图等非 md 编排以后再说。

### 5.2 项目

- **项目本身也是一张卡片**：即一张"根编排卡"，存放在 `Weaving/<项目>/` 下。
- 项目目录用来存放在该上下文中产生的分支卡与新卡片。
- 项目可以被嵌入到别的项目里。

### 5.3 写时复制分支

1. **嵌入时**：只是纯引用 `![[原卡id]]`，不复制文件，显示的是原卡的实时内容。
2. **首次在某个上下文中编辑时**：在该上下文的项目目录下生成分支卡，写入 `upstream` 与 `base`；把原卡当时的内容存进 `.finnegan/bases/<sha256>.md`；编排正文中的引用改指向分支卡 id。
3. **原卡之后发生变更时**：检测到 `hash(原卡当前内容) ≠ base`，在分支卡上提示"原件有更新"，可以用 base / 原件 / 分支 三份内容做三方合并。
4. **分支归属**：在谁的上下文里编辑，分支就属于谁。例如 B 嵌入 A、A 嵌入 X，在 B 中编辑 X，生成的是 B 的 X 分支，A 不受影响。

### 5.4 同步方向

- **原件 → 分支**：自动检测并提示，由用户决定是否合并。
- **分支 → 原件**：只能**手动触发**（显式的 push），不会自动回写。

### 5.5 base 快照库

- 自己维护 `.finnegan/bases/`，按内容 hash 寻址，相同内容只存一份。
- 不依赖数据根是否为 Git 仓库；没有任何分支引用的快照可以被清理。
- 不采用 `git hash-object` 方案：未被引用的对象会被 `git gc` 清理，需要额外维护 refs，复杂度过高。
