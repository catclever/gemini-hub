# 对话流卡片（Chat Log Cards）设计与实现规范

**日期**: 2026-10-14  
**目标**: 将粘贴的多选聊天记录（如微信），自动清洗并无损原样压入 Markdown 卡片，LLM 提炼精准标题，起止时间升维为元数据。

---

## 1. 核心设计原则

1. **正文零损（Raw is King）**：
   - 原始对话文本 100% 保留其人名、换行与真实发言内容，绝不做有损的摘要重写。
2. **剔除行内时间戳噪点**：
   - 过滤掉夹杂在每条消息之间的无意义时间戳行（如 `2026年10月14日  8:15`），让连续发言自然聚拢。
3. **时空坐标升维（Temporal Metadata Lifting）**：
   - 从原始记录中提取第一条消息时间为 `started_at`，最后一条消息时间为 `ended_at`。
   - `created_at` 默认与 `started_at` 对齐，确保卡片在 Finnegan 宇宙舞台与记忆潮汐（Memory Tide）中的时空坐标精确对应灵感发生的真实时刻。
4. **LLM 纯粹定位为“标题提取策略”**：
   - LLM（Gemini 3.8 Flash）不修改正文，只负责通读对话后提炼一个自然贴切的 `title`，并提取 `participants` 发言人列表。
5. **表现层优雅排版（Screenplay Typography）**：
   - 遵循 Finnegan 现有卡片体系，不搞特殊角标（无类似“8条对白”的牛皮癣徽章），不搞定制复制按钮（复制与微调标题属于全局通用交互）。
   - 聚焦态（420×420）针对对白格式进行舒适的剧本级行距与发言人微高亮排版。

---

## 2. 数据契约与存储规范

### 2.1 Frontmatter 规范
```yaml
---
id: 01JAX9K2...
type: chat_log
title: 吐槽 Argon 额度消耗与大模型说话语气
participants: [巧先生, 枫]
started_at: 2026-10-14T08:15:00+08:00
ended_at: 2026-10-14T09:13:00+08:00
created_at: 2026-10-14T08:15:00+08:00
---
```

### 2.2 正文规整示例
```markdown
巧先生:
哥们 argon暂时体验一下就好~~我刚15分钟跑掉10% 就改了几个前端交互 简直了……

枫:

巧先生:
按这么算5小时额度只够用1个多小时的hhh
体验下 看看有什么区别~~
```

## 3. 架构分工与模块协作

1. **输入检测（Frontend / Omnibar）**：
   - 粘贴内容时，正则检测是否匹配对话特征（多行出现 `^.+?\n\d{4}年\d{1,2}月\d{1,2}日.*?\n` 或常见多行 `Speaker:\n` 结构）。
   - 若匹配，触发对话处理通道。
2. **解析与清洗（Backend or Shared Lib）**：
   - 提取起止时间戳转为 ISO 8601。
   - 剔除时间戳行，合并同一人连续发言。
3. **LLM 标题提取（Bugu / LLM Router）**：
   - Prompt: 给定对话内容，提取 1 个简短精炼、生动的标题，以及参与者名单。
4. **卡片落地（Core Scattering / Volatile）**：
   - 优先作为 Volatile 临时卡片飞入 CosmicStage，敲回车 Promote 写入 `<home>/Scattering/YYYYMMDD-HHMM-<slug>.md`。
