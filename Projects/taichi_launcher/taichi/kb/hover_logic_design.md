# 太极 (TaiChi) 刘海状态与悬停逻辑设计文档

本文档详细记录了 TaiChi Launcher 核心刘海（Island）的视觉形态、悬停（Hover）交互逻辑，以及状态之间的切换与清理机制。

## 1. 播放状态 (Playing)
当系统中有媒体正在播放时，刘海的主要目标是提供信息展示与快捷控制。

- **默认形态（长刘海）**：处于 `.idle` 状态但因为有音乐数据，宽度会展开，左右两侧显示快捷图标（如：左侧旋转唱片，右侧波形图和App图标）。
- **切歌时（歌名展示状态）**：每当歌曲发生切换，刘海自动变宽并拉长进入 `.trackChanged` 状态，显示歌曲名和歌手信息。持续 5 秒后，自动收回为“长刘海”。
- **两段式悬停逻辑 (Hover)**：
  1. **第一段（展出歌名）**：当处于长刘海形态时，鼠标只要移入刘海，等待 **0.5 秒**后，刘海会展开成**歌名展示状态**。
  2. **第二段（彻底展开面板）**：在歌名展示状态下，鼠标继续保持悬停 **1.5 秒**，刘海将彻底向下展开，露出完整的播控面板（`.expanded` 状态）。

## 2. 非播放状态 (Paused / Idle)
当没有任何媒体播放，或者媒体被手动暂停时，刘海的主要目标是尽量隐藏，仅在用户刻意交互时提供面板入口。

- **默认形态（短原生刘海）**：系统没有任何图标，仅有一条覆盖物理刘海区域的纯黑短条（宽约 190px，高约 38px）。
- **两段式精确悬停逻辑 (Hover)**：
  1. **第一段（唤出图标 或 功能菜单）**：鼠标只要触碰到物理刘海范围内的**任何区域**（36px 深度范围内），短刘海会立刻向左右延展，进入“长刘海”状态，丝滑显示出左右两侧的控制图标。如果当前没有任何歌曲记录，等待0.5秒后会进入功能选择菜单(`.modeSwitcher`)。
  2. **第二段（呼出面板）**：用户若想打开播控面板，需刻意将鼠标**向上顶，进入刘海正中央顶部的核心 12 像素区域内**。
     - 进入核心 12 像素区后，触发 **1.5 秒** 的倒计时。
     - 若倒计时期间鼠标滑出 12 像素区域（如下滑到 13~36 像素区域）或横向移到了左右图标上方，倒计时会**立即取消**。
     - 停留满 1.5 秒，彻底展开播控面板。
- **离开逻辑**：无论在任何阶段，只要鼠标完全离开刘海区域，刘海会立刻收缩回纯黑的“短原生刘海”。

## 3. 功能选择菜单状态屏蔽逻辑 (Menu Focus Protection)
当刘海展示的是 **功能选择菜单**（包括无媒体时的 `.modeSwitcher` 或者是多播放器选择时的 `.multiAppList`）时，系统必须保护用户的点选焦点，因此将**全局屏蔽所有多段式的自动往下展开的悬停逻辑**。
- 如果鼠标在菜单界面上或者菜单周围的刘海区域悬停（甚至滑到最顶部 12px 区域），**绝对不会**触发二段式的“播控面板”展开（完全屏蔽 1.5 秒展开倒计时）。
- 如果状态切入到上述任何菜单模式，任何正在进行中的展开计时器都会被立刻强制清理，保证当前菜单的使用焦点不被打断。

## 4. 状态切换与退出机制 (State Transitions & Cleanup)

- **播放 -> 非播放 的切换**：
  - 当用户在播放器中点击“暂停”，核心状态并不会立刻销毁。刘海依然保留着歌曲数据。
  - UI 表现：波形图停止跳动，唱片停止旋转，悬停逻辑自动从“播放状态逻辑”切换为“非播放状态逻辑”（极其严苛的 12px 判定）。
- **App 彻底退出逻辑 (Graceful Exit)**：
  - `MediaObserver` 全局监听了系统的应用退出通知 (`NSWorkspace.didTerminateApplicationNotification`)。
  - 当某个 App 被“杀掉”或正常 `Quit` 时，TaiChi 会对比该 App 的 Bundle ID 与当前展示的媒体 ID。
  - 若退出的是当前正在展示的媒体，TaiChi 会**立即清空**所有的核心媒体数据（`title`、`artist`、`artworkData` 以及将 `isPlaying` 设为 `false`）。
  - UI 表现：感知到 `title` 为空且不播放后，刘海 UI 会瞬间干脆利落地缩回到“短原生刘海”状态，无缝退出，假装无事发生。
